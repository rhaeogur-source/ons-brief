# 실습 06. 출동 전 원인 브리핑 카드

**난이도** 중 · **예상 시간** 90분 · **핵심 기능** 여러 파일 연결(조인) 분석, 근거를 단 추론 요약

## 프로젝트 개요

현장 엔지니어는 출동 지시를 받으면 "이 기지국 전에도 이랬나? 장비는 언제 바꿨지?"를 여러 시스템에서 따로 찾아봅니다. 과거 기록을 미리 모아 보면 **같은 증상이 반복되는 기지국과 그 원인**이 보입니다. SKT의 품질관리 AI(A-STAR)도 현장 조치 이력을 학습해 원인과 조치를 추천합니다.

**목표:** 알람이 난 기지국마다 **출동 전 브리핑 카드**(예상 원인, 근거, 챙길 자재)를 자동으로 만듭니다.

## 기본 요구사항

1. 10/8 알람이 난 기지국을 기준으로 장비이력·조치이력을 연결
2. 기지국별 카드: 오늘 알람 요약 / 과거 같은 증상 횟수 / 가장 유력한 원인 / 근거(어떤 기록에서 나왔는지) / 챙길 자재·주의사항(고소작업 등)
3. 결과물: 기지국별 md 카드 또는 카드 목록 HTML
4. **근거 없는 추측은 "추정"으로 표시**

## 도전 과제

- 반복 장애가 많은 기지국 순위 매기기
- 같은 펌웨어·같은 연식 장비끼리 비교해 원인이 공통인지 확인하기
- 카드를 "지금 바로 출동" / "원격 조치 먼저" / "다음 정기점검 때"로 분류하기

## 시작 프롬프트 예시

```
세 파일(알람 로그, 장비이력, 조치이력)의 관계를 먼저 설명해줘. 어떤 컬럼으로 연결되는지, 연결이 안 되는 경우는 없는지도 확인해줘.
```
